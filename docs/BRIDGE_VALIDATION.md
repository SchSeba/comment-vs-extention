# Codex integration validation

**Automatic submission to the selected IDE chat — `BLOCKED`**

The test host is rootless Podman Desktop on Windows with a Fedora 44 x86-64 container. Code-server 4.143.1 runs VS Code 1.143.1 with a Linux workspace extension host and browser UI. The container runs as `tasktracker` (UID 1001). It has Git 2.56.0, Node.js 22.23.1, and Codex CLI 0.164.0. The test image pins official IDE extension `openai.chatgpt` 26.908.40401, which bundles Codex 0.154.0-alpha.6.2. The CLI and bundled binary both discovered `list_pending_comments` and `record_comment_reply` over stdio MCP SDK 1.32.2. The auto-updated extension 26.1021.22027 also discovered the tools, but its webview repeatedly timed out in the authenticated browser tests.

- `chatgpt.addToThread` and `chatgpt.addFileToThread` attach editor context. `chatgpt.newChat` and `chatgpt.newCodexPanel` create a new destination. [Codex IDE commands](https://learn.chatgpt.com/docs/developer-commands?surface=ide)
- The installed TODO CodeLens command takes `{ fileName, cwd, line, comment }`. Its handler creates a conversation for the TODO and navigates to it. It has no selected-conversation argument or addressed-submit acknowledgement.
- The installed manifest exposes a development-only CLI binary override. No public configuration in that manifest exposes the IDE-owned app-server transport or the selected conversation.
- The browser's workspace-host probe activated `openai.chatgpt` 26.1021.22027, observed no public exports, and enumerated its registered commands. The additional registered commands controlled sidebar visibility and focus.

**Authenticated, user-submitted roundtrips — passed in both clients**

- In the browser's integrated terminal, ran a real `codex exec` turn, then used `codex exec resume` with its thread ID and the copied review follow-up. The test launcher used workspace-write permissions for the disposable clone and a separate process session to capture JSON events. The interactive TUI reached its folder-trust prompt, where the browser automation stalled. The completed terminal roundtrip covers `exec` and `resume`.
- In the official 26.908.40401 Codex sidebar, submitted the initial prompt and the copied review follow-up through the same composer and observed both turns in the same chat.
- Each client edited its own clone, processed two comments written in the native Source Control diff, applied `Hi` → `Welcome` and `?` → `!`, and produced two short chat summaries and two matching MCP replies. Each clone retained only the expected unstaged change to `greeting.js`.
- Codex CLI 0.164.0 discovered the installed `$handle-comments` shortcut in an already-running app-server process. The IDE's bundled binary also listed it. A signed-in CLI turn submitted as `$handle-comments` applied a seeded comment in a disposable clone and saved its summary. The 0.1.1 test image installed the shortcut and registered MCP on first boot.
- The 0.1.2 browser test opened a parent folder containing two sibling Git repositories. Both appeared in Source Control and accepted native comments. A signed-in `$handle-comments` turn started from the first repo in the integrated terminal, changed its file, and saved its reply. The second repo's file and comment stayed intact.
- The browser test resolved one comment with the checkmark, resolved only answered comments in bulk, and preserved the Codex reply after reload. Clean Review canceled without changes and then cleared only the selected worktree when confirmed. The CLI resolved one answered comment via `$mark-resolved-review` and cleared two comments via `$clean-review` after one interactive approval. Non-interactive cleanup was rejected by Codex's approval policy.
- The 0.1.3 browser tests used three comments in the same file and a separate sibling repo. The first fix inserted a line and changed the second comment's target. The integrated terminal refreshed the later comments, reported the changed target at line 4 and the moved target at line 5, and verified that the first fix had already satisfied the second comment. The official sidebar completed the same scenario using the copied follow-up. Both runs saved three individual replies, which appeared after reloading, and preserved the sibling repo's file and review record.

The working handoff is a user-submitted follow-up in an existing CLI or IDE chat. `Local Review: Inspect Codex Integration` shows the installed version and registered commands without making a provider submission. [Required Codex API](REQUIRED_CODEX_API.md)

## Branch and thread isolation audit

Tested Local Review 0.1.3 in a disposable code-server 4.143.1 instance with VS Code 1.143.1, Chrome 153.0.8010.36, Git 2.56.0, Node.js 22.23.1, Codex CLI 0.164.0, and the installed Codex extension 26.908.40401. The browser used the native diff and the test client called the packaged MCP server over stdio. The audit used a fixture reply without signing in to Codex or running a model turn.

- **Source Control → Changes → ⋯ → Local Review: Copy Codex Follow-up** copied a prompt for the selected worktree. Submit it manually in the existing Codex chat. The same action is available from the Command Palette.
- A comment added on `main` remained visible and pending after switching to `feature` in the same directory. MCP read the working file from `feature`. A reply, bulk resolve, and cleanup on `feature` acted on that same comment.
- A linked Git worktree had an empty pending list, rejected a reply to the first worktree's comment ID, and removed zero records on cleanup. A symlink alias to the original checkout shared its review records. A replacement Git repository at the same absolute path inherited pending records.
- The fixture reply appeared in the native thread and changed its label to **Addressed**. The thread had no visible reply editor and was absent from the next pending list.

Local Review 0.2.0 passed the browser and packaged MCP checks in the same code-server environment. The clipboard button copied the worktree and branch scope. With several repositories open, the action in the repository's overflow menu copied that repository's scope. Switching to `feature` hid the saved `main` thread, closed the unsaved native draft, and produced an empty pending list. The old copied scope was rejected, including for cleanup. Switching back to `main` restored the saved thread. A linked worktree rejected the foreign ID and had no records to clean. Automated tests also covered reftable and detached HEAD, replacement checkouts at the same path, nested Git ownership, explicit import of older comments, and competing follow-up and bulk resolve operations.

A signed-in Codex CLI 0.164.0 test submitted two copied prompts via `codex exec resume` to the same conversation. Codex read pending feedback and refreshed context before each edit. It changed the fixture label to `reviewed`, then to `REVIEWED` in response to **Add Review Follow-up**. Both summaries appeared in the same native VS Code thread and the pending list emptied after each answer. The 0.2.0 authenticated check used the CLI. The older sidebar results above cover manual paste and submit.
